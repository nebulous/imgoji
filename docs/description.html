how it works

A quadtree that blends emoji until the picture appears.

The first emoji approximates the image. The next four refine the quadrants, the next sixteen their sub-quadrants, and so on. Each glyph blends over its parent, so the approximation converges instead of plateauing.

  1. 01

    Subdivide

    A breadth-first quadtree splits the frame into ever-smaller regions. The sweep reads as a raster scan within each level.

  2. 02

    Blend

    Each cell picks the single emoji that, blended over its parent’s render, best matches the original region. The operator is ordinary alpha compositing. The browser decodes it with no custom code.

    A′ = (1−a)·A + a·E
  3. 03

    Prefix

    Cut the string and what’s left is still a valid, coarser image. Prefixes of 1, 5, 21, 85 mark the 1×1, 2×2, 4×4, 8×8 grid levels.

features

No font to distribute. The OS already ships one.

📝

Pure plain text

The encoded form is emoji. It transmits as text: chat, email, source control, a tweet. No container or encoding wrapper.

🪶

Zero assets

No font or image is bundled. Glyphs are referenced by codepoint and resolved by the viewer’s system emoji font. The decoder is, at its core, the browser’s own compositor.

🔭

Resolution-independent

Positions are fractions of the frame and each glyph scales to its region. The same string renders crisp at a favicon or a billboard.

📶

Progressive prefix

Every prefix is a valid, coarser frame. Stream the head and it reads as a recognizable image; the tail only adds detail.

🌱

Seedable anchors

Pin the first cells to chosen emoji (a globe for a planet, a face for a portrait) so the head carries a thematic anchor while the tail adds detail.

🔀

Cross-platform by design

One string renders as Apple emoji here, Google there, Noto elsewhere. The drift isn’t a bug to suppress. It’s the affordance the format is built around.

the format

One grammar, three serializations.

The model is an ordered list of placed, transformed glyph subjects rendered back-to-front. JSON, a compact DSL, and SVG are three views of the same scene, chosen per use case.

Lowercase letters are operators, uppercase [0-9A-F] is data. More hex digits mean finer precision, not a bigger range. A shorter prefix is always a valid coarser value. Read the full spec →

one string, three renderers

Same emoji, different strokes per device.

Encode on a Mac and the head reads as Apple emoji. Open it on an Android phone and Noto paints the glyphs. The format doesn’t fight this. Devices ship a glyph set, so referencing glyphs by codepoint ships no font of its own.

faq

Good questions.

Is this a serious codec?

It’s an experiment that takes itself seriously. The encoding model (a quadtree of blended glyphs with a prefix property) converges: RMS on the reference image drops from ~142 to ~51 across depth 0→6. It is not competitive with JPEG or AVIF on size or fidelity. It is competitive on charm and portability.

Why does it look different on my friend’s phone?

Because the viewer’s system emoji font supplies the pixels. Apple, Google, and Noto draw the same codepoints differently, so the same string renders as three related-but-distinct pictures. This drift is intended, not a defect.

What stops the reconstruction at one color per cell?

Blending, not replacing. Each cell composites its chosen emoji over its parent’s accumulated render with a fixed alpha (0.7 by default). The final color at a pixel is a weighted chain from the root down, and each level shrinks the residual, so the output converges past the discrete emoji palette instead of plateauing.

Can I hand-write a scene?

Yes. The DSL is written by hand and pasted straight into markup: emoji plus ASCII [0-9A-F] and lowercase letters, with no quoting or escaping. A glyph followed by a lowercase letter is a positioned sprite; otherwise it’s codec body.

What’s in the palette?

Unicode 15.1.0 Emoji-property codepoints across the classic pictograph ranges (modifiers and components excluded), plus solid color-anchor emoji (circles and squares, including black and white) to extend the palette’s convex hull so blending can reach extreme colors.
